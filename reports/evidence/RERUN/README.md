Two backend tests that used `invoice_id` on `invoices.outstanding` were corrected.
- D23 (fixed in this pass, found on the memory-bound ops2 install): after the engine evicted an entity's history locators (bounded working set), intent answers cited nothing — `evidence_refs: []`, `entry_ids: []`, no disclosure — while `GET /api/entities/<type>/<id>/state` for the same entity disclosed `history.evicted_use_cold_read` and served the entries from PostgreSQL. Fixed: `Answer::finish` (crates/query) adds the same `history.evicted_use_cold_read` missing-input marker and a `coverage.evidence_evicted_entities` count, and the engine's query handler (apps/engine) fills `entry_ids`/`evidence_refs` from the indexed cold path (`entity_entries`, bounded by MAX_EVIDENCE, `coverage.evidence_source: postgresql_cold_read`).
- Observation D24 (not fixed): `customer.delivery_reply` reports prior communications with `message_id: "communication:<order>"` (the reducer's record id) instead of the source's message identifier from the `communication.observed` payload (`message`); the summary/actor/time are preserved. - Observation D26 (not fixed, found by the installed-stack coverage run): for intents that take an `order_id`, an `as_of` query replays only that order's scope (`replay_scoped`), so tenant-wide datasets (tracking, policy) are absent from the replayed state and `shipments.attention`, `shipments.promise_risk` and `payments.recovered_attempts` answer `partial` under `as_of` where the latest-committed answer is `complete` (21/24 as_of agreement; the other 21 intents and all 6 restart re-checks are identical).
